insaneBOOT - ChangeLog
======================

2026-09-13 (suite)
- Detection version TOS : getcookies_sup lit os_version (_sysbase $4f2
  +2) dans c_tosver. Nouvelle directive .showtos -> affiche "TOS x.xx"
  (octet bas en BCD). Valide sous Hatari via --conout : TOS 2.06 et
  EmuTOS (qui s'annonce 2.06). Compile 68k + ColdFire.
  NB : EmuTOS renvoie os_version=$0206, donc non distinguable d'un vrai
  TOS 2.06 par ce seul champ (cookie ETOS a etudier pour cela).

2026-09-13
- Nouvelle directive .jar N : reserve un cookie jar resident de N
  cookies (remplace jarXXX.prg). Max 128, 0/absent = desactive.
  * parser.s   : token .JAR, handle_jar (clamp a JARMAX), v_jar, et
                 buffers BSS jarbuffer + v_basepage.
  * supcode.s  : installjar / installjar_sup (superviseur) : recopie
                 les cookies existants, ecrit le terminateur {0,capa}
                 et repointe _p_cookies ($5a0) sur jarbuffer.
  * autoexec.s : sauvegarde de la basepage, installation apres
                 parseconfig, et sortie par Ptermres (au lieu de
                 Pterm0) quand .jar est utilise (reste resident).
  * autoexec.cfg : documentation de .jar.
  Compile OK sur les deux cibles (68k et Coldfire cf5474).
- Etude .foldr : abandonnee. Desassemblage de FOLDRXXX.PRG (capstone)
  -> patch d'internes GEMDOS, no-op sur TOS >= 1987 (os_dosdate) et
  table d'adresses codees en dur pour 4 ROMs 1985-86 uniquement.
  Inutile sur EmuTOS / TOS 1.62 / 2.06 (FRB dynamiques). Non implemente.

2026-09-11
- parser.s: ajout de 4 flags combines resolution + CPU :
  .ITEMSTC000 (couleur + 68000)
  .ITEMSTM000 (mono/haute res + 68000)
  .ITEMSTC020 (couleur + 68020)
  .ITEMSTM020 (mono/haute res + 68020)
  -> tokens, handlers et entrees chktoken correspondants.
- autoexec.cfg : documentation des nouveaux flags combines.
- Constat prealable : .ITEM020 (68020) existait deja, ainsi que
  item000/010/040 ; seule la combinaison resolution+CPU manquait.
